## 2026-03-23 - Prevented Unnecessary Re-Renders in TaskBoard List Items
**Learning:** React list rendering in the Kanban Board can get expensive when local state inputs (like "New Task Title" input fields) trigger re-renders on every keystroke. Using inline arrow functions for callbacks (like \`onClick={() => onClick(task.id)}\`) on list items causes them to fail shallow equality checks in `React.memo()`.
**Action:** Stabilized callback functions in list parent components using \`useCallback\`, updated child components to accept raw identifiers instead of wrapper functions for events, and wrapped the child list item components in \`React.memo()\` to effectively decouple them from the parent's generic state updates.
## 2026-03-23 - Prevented Unnecessary Re-Renders in Agent Thread and Task Detail Panels
**Learning:** In chat and task panels (`AgentThread`, `TaskDetail`), keystrokes in input fields cause the entire panel to re-render. Since historical event items (`EventBubble`, `TimelineEvent`) perform expensive markdown parsing (`FormattedText`), this causes significant input lag. Passing volatile props (like Zustand arrays or unstabilized callbacks) directly to list items breaks `React.memo()`.
**Action:** Wrap expensive list item components in `React.memo()`. Stabilize their event handlers using `useCallback` and read dynamic values (like `sessions` arrays) directly inside the callback or click handler using `.getState()` from the Zustand store instead of passing them as props.
