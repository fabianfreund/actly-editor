## 2024-12-11 - Arbitrary Command Execution via Unvalidated External Binaries
**Vulnerability:** Found arbitrary command execution risk in Tauri commands (`check_codex_path`, `start_codex_server`). The app passes an unsanitized, user-provided string to `tokio::process::Command::new(bin)`. This allows a malicious user or extension to run any executable on the system by providing a path like `/bin/sh` or `/usr/bin/curl` instead of the expected `codex` binary.
**Learning:** In Tauri backends, when allowing users to configure custom paths for required external tools (like the codex app-server), failing to restrict the actual executable name allows total bypass of intended use. Relying on default fallbacks (e.g., `unwrap_or("codex")`) is insufficient if the user string is taken verbatim. Path suffix checks must be robust against maliciously named directories (`/path/to/my_fake_codex.exe/malicious_bin`).
**Prevention:** Always validate user-provided executable paths before passing them to `Command::new()`. Extract the true filename using `std::path::Path::new(&normalized_path).file_name()`. On platforms where paths can cross boundaries, always replace Windows backslashes (`\`) with forward slashes (`/`) before extracting the filename to prevent evasion (e.g., passing `malicious.exe\..\codex.exe` which might bypass a naive `ends_with` check).
