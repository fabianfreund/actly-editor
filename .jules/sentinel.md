
## 2024-05-24 - Arbitrary Code Execution via Unvalidated Executable Path in Tauri Commands
**Vulnerability:** The Tauri backend commands `check_codex_path` and `start_codex_server` accepted a user-provided `codex_path` (or `path`) and passed it directly to `tokio::process::Command::new(bin)` without validating the executable name. This allowed an attacker to specify arbitrary executables (e.g., `/bin/bash` or `rm`) and execute arbitrary code on the user's system under the context of the application.
**Learning:** In a desktop application where the frontend can invoke backend commands with arbitrary arguments, passing user-provided strings directly as the first argument to process execution functions (like `Command::new`) is a critical security risk. It bypasses any intended restrictions on what the backend is supposed to run.
**Prevention:** Always strictly validate user-provided executable paths. Instead of blindly trusting the input, extract the file name from the path and ensure it exactly matches a known, allowlisted executable name (e.g., verifying `file_name.to_lowercase() == "codex" || file_name.to_lowercase() == "codex.exe"`). Reject any request that fails this validation.
